# Changelog

## 0.2.0: script-enforced workflow
Why: in a real run the v0.1 agent skipped steps, accepted its own evidence as "precedent", and the
gate had to be patched by hand. Prose rules were not enough, so the workflow moved into a script.

- `scripts/lltt.py` is a state machine (`init`, `next`, `gate`, `status`, `finish`). The agent only sees
  the current phase and cannot advance until the gate passes.
- Five gates with concrete checks (sources must exist, every fact needs `file:line`, decision rows must
  cover every traced file, probes must be stamped by `ProbeRecorder`, ...).
- Probe results are HMAC-stamped with a per-run key and must be backed by a probe test in `tests/Probes/`.
- Edge cases need `VERDICT` (SAME / DIFFERS / NO-RECOMMENDATION). DIFFERS requires a pending test for the
  recommended behavior.
- Circular evidence is rejected: a precedent that is the code under test (same file, within 5 lines) fails.
  A recommendation needs a precedent elsewhere, a laravel.com/docs URL, or `none established`.
- Status codes written in CURRENT must exist in the probe's observed data. A probe that contradicts the
  code reading forces an EDGE test.
- Edge ids must be continuous (no silently dropped edges).
- Only tests added after `init` are checked (snapshot), so existing project tests are never flagged.
- The script runs the tests itself, one file at a time. The agent cannot claim a pass.
- The report and the final answer are generated by `finish`, not written by the agent.
- Skill files are hash-checked (`MANIFEST.sha256`); `.trace/state.json` is signed.
- Per-phase timing is recorded to find slow steps.
- Removed `detect_env.sh` and `verify_tests.py` (folded into `lltt.py`).
- 45 unit tests that simulate agents, including ones that cheat.
